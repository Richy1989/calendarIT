_Changes since `v0.13.0`._

This release gives admins a full user list, fixes start-up with blank settings, and moves the published image to `richy1989/24seven`.

✨ New Features

- **Settings → Users** (was *New accounts*) lists every account on the server, with when it was last active. Admins can activate, disable, delete, make admin or remove admin rights, and create a password-reset link to hand over.
- Disabling an account signs it out everywhere at once (web, app and CalDAV) and keeps its data. A disabled account gets no reminders, mail or feed refreshes until it is enabled again.
- You can't disable, delete or demote your own account, so a server always keeps an admin.

🐛 Fixes

- A setting left blank (`SMTP_USE_SSL=`, as `.env.example`, Compose and Unraid pass an empty option) now means its default. Before, it could stop the server at start-up (0.13.0 with a blank `SMTP_USE_SSL`).
- Operator commands (`activate-account`, `make-admin`, `reset-password-link`) work again with `docker exec` in the published image. They used to stop because only the server process has the signing key.

📦 Deployment & Docs

- The published image is now **`richy1989/24seven`**. On Unraid, change the template's repository from `richy1989/calendarit` to `richy1989/24seven` (your `/data` stays as it is).
- New `docker-compose.image.yml` runs the published image without building. The README shows how.
- The database is migrated automatically. Existing accounts stay as they are.
- The release check now starts the image with every optional setting blank and runs an operator command in it.
- This tag releases the CalendarIT server and web app. Android APKs are published under the separate `24seven-v*` tags. The app's new CalDAV accounts (no 24seven server needed) come with the next app release.
